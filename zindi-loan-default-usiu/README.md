# Loan Default Prediction — Zindi x USIU-Africa Data Science Hackathon

A machine learning pipeline that predicts the probability a loan defaults, built for the Zindi credit scoring challenge hosted with the USIU-Africa IT Club. The client is a private asset manager operating in several African financial markets.

This was USIU-Africa's first time competing on Zindi as a school. Our team of three finished with the highest score among the participating USIU groups.

## The challenge

- **Task:** predict loan default (`1` = default, `0` = repaid) for loans in Kenya and Ghana.
- **Generalisation test:** training data is Kenya only; the test set contains Kenya and Ghana, so the model has to work in a market it never saw.
- **Metric:** F1 score on hard `0/1` predictions (not AUC, not probabilities).
- **Data quirk:** a customer can appear on many rows, and one loan can appear on several rows with different lender IDs (a loan funded by multiple lenders).
- **External data:** FRED economic indicators for Kenya and Ghana (inflation, exchange rate, interest rates, unemployment, precipitation, fossil fuel use).

## Approach

1. **Economic indicators merge.** Pivoted the indicator file to one row per country and year, joined on `country_id` + disbursement year, and carried the latest known year forward for loans disbursed after the last year in the indicator file. This gives the model macro signal for Ghana.
2. **Leakage fix.** Our first model scored a validation AUC of about 0.98, which was too good to be true. Rows from the same loan and the same customer were landing in both training and validation. We switched to group-based splitting on `customer_id` (`GroupShuffleSplit`, then `GroupKFold`).
3. **Feature engineering.**
   - `interest_amount` and `repayment_ratio`: cost of the loan relative to the amount borrowed
   - `lender_funding_ratio`: share of the loan funded by the lender on that row
   - `customer_loan_number`: which loan this is in the customer's history (repeat-borrower signal)
   - Disbursement year, plus the merged economic indicators
4. **Modelling.** LightGBM and CatBoost with class weighting for the heavy imbalance (about 1.8% defaults). The better of the two on a held-out customer group picks the algorithm for the final run.
5. **5-fold GroupKFold cross-validation.** Out-of-fold predictions cover the whole training set, and test predictions are averaged over the five fold models.
6. **Threshold tuning.** Because the metric is F1, the probability cutoff is tuned on the out-of-fold predictions rather than fixed at 0.5.

## How to run

1. Install dependencies: `pip install -r requirements.txt`
2. Download the challenge files from the Zindi challenge page and place them in `data/`:
   - `Train (1).csv` (the notebook's `TRAIN_FILE`)
   - `Test.csv`
   - `economic_indicators.csv`

   If your filenames differ, edit the config cell at the top of the notebook.
3. Open `notebooks/loan_default_pipeline.ipynb` and run all cells in order.
4. The submission is written to `outputs/submission_cv.csv` with columns `ID` and `target` (binary `0/1`), ready to upload to Zindi.

All random seeds are fixed (`random_state=42`), so reruns should reproduce the same results.

**Hardware:** runs on a normal laptop or Google Colab CPU. Expect a few minutes end to end, with the 5-fold training being the longest step.
